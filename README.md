# AssetSentinel AI — Phase 1 (Demo MVP)

A polished, fully static web application for **industrial roof and building-exterior inspection reporting** in Malaysia. This is a demonstration MVP: every property, inspection, finding, review and report in the app is **fictional demo data**, clearly labelled `DEMO`.

> ⚠️ **Demo mode:** No real customer data. No AI is connected in Phase 1 — anything that looks like an "AI finding" is a scripted demo suggestion. Nothing here is a structural certification.

---

## What it does (Phase 1 workflow)

```
Property → Inspection → Images → Findings → Human Review → Approved Report → PDF
```

- **Dashboard** — property / inspection / finding / report counters, findings-by-severity breakdown, review-pipeline status, recent activity.
- **Properties** — list, create, edit, and a detail view per property (4 demo industrial properties: Shah Alam, Klang, Puchong, Rawang).
- **Inspections** — per-property list; new-inspection wizard; image gallery with upload controls (demo mode: uploads live in the browser session only and are **not** persisted).
- **Findings editor** — click-to-place photo annotations (react-konva), defect type, severity, notes, recommendations.
- **Human review** — approve / edit / reject each finding, with a review history trail. Reports are **blocked** while any finding in the inspection is unreviewed.
- **Reports** — professional HTML preview built only from approved findings, with evidence photos and annotations, plus one-click **PDF export** (jsPDF, generated in-browser).
- **Settings** — company profile, users/roles preview, pricing tiers, branding accents. All demo, stored locally.

## Demo imagery

The `public/images/` folder contains **synthetic, procedurally-generated SVG scenes** (generated by `scripts/gen-images.mjs` at build time) — clearly fictional warehouse exteriors/roofs. No photos of real premises are used, and no claim is made that any real defect has been identified.

## Run it on your Mac (beginner-friendly)

You need Node.js 18.18+ (Node 20 LTS recommended). Check with:

```bash
node -v
```

If you don't have Node, install it with [Homebrew](https://brew.sh): `brew install node`

```bash
# 1. Go to the project folder
cd ~/projects/assetsentinel-ai     # ← adjust to wherever you copied it

# 2. Install dependencies (once)
npm install

# 3. Start the dev server
npm run dev
# → open http://localhost:3000

# 4. Run the tests
npm test

# 5. Build for production (static export → out/)
npm run build
# → the ready-to-host site is in ./out
```

To preview the production build locally:

```bash
npx serve out
# → open the URL it prints
```

## Tech stack

| Layer | Choice |
|---|---|
| Framework | Next.js 15 (App Router), **static export** (`output: "export"`) |
| Language | TypeScript (strict) |
| Styling | Tailwind CSS 3, navy/teal enterprise theme |
| UI primitives | Hand-rolled shadcn/ui-style components (Button, Card, Badge, Input…) + Lucide icons |
| Annotations | react-konva + konva |
| PDF | jsPDF (client-side generation) |
| Data | Typed local mock data (`src/lib/data.ts`) with a repository seam (`src/lib/repo.ts`) prepared for Supabase |
| Tests | Vitest (workflow logic: review gating, severity, slug generation, data integrity) |

## Architecture notes (Supabase-ready seams)

All data access goes through `src/lib/repo.ts`, which today reads/writes the in-memory demo store and mirrors mutations to `localStorage`. Swapping in Supabase later means implementing the same `Repo` interface against `supabase-js` — no UI code changes.

```
src/
  app/            # App Router pages (all statically pre-rendered)
  components/     # ui/ primitives + app/ feature components
  lib/
    types.ts      # domain model (Property, Inspection, ImageAsset, Finding, Review…)
    data.ts       # DEMO seed data (4 properties, 3 inspections, 15 findings, reviews)
    repo.ts       # repository seam (in-memory + localStorage mirror in demo mode)
    workflow.ts   # review gating / status derivation (pure functions, unit-tested)
  hooks/          # useDemoUploads (session-only upload simulation)
public/images/    # synthetic SVG demo scenes (generated, not real photos)
```

## Explicit safety posture

- No real customer data, no secrets, no API keys.
- No external AI calls — Phase 1 has zero network calls at runtime.
- No AI-accuracy claims; every suggestion is labelled a demo suggestion.
- No claims of structural certification or engineering sign-off.
- Demo uploads are explicitly explained in-app as session-only (they do **not** persist).

## What's mocked vs. real

| Area | Status in Phase 1 |
|---|---|
| Domain data | Mocked (typed demo seed) |
| Persistence | localStorage mirror (demo only) |
| Image upload | Session-only demo, not persisted |
| AI finding suggestions | Scripted demo labels only |
| PDF export | Real (client-side jsPDF) |
| Annotations | Real (react-konva) |
| Auth / users / roles | Static preview only |

## Before real customer use (roadmap beyond Phase 1)

1. Supabase (or equivalent) integration behind the `Repo` seam, with row-level security.
2. Real object storage for inspection imagery (signed URLs, retention policy).
3. Actual model-assisted defect triage, with accuracy measured and disclaimed — never auto-approved; human review stays mandatory.
4. Accounts, roles and audit trail on a real backend.
5. Professional review of report wording by a qualified inspector/engineer before any customer-facing claim.
